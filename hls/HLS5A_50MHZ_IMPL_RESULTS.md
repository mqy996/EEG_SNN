# HLS-5A 50 MHz Vivado out-of-context implementation 结果

## 结论

**50 MHz HLS/Vivado out-of-context implementation：PASS。**

使用本机 Vitis/Vivado 2025.1，对 `hybrid_lif_head_q12_6` 在 `xc7z020clg400-1`、20 ns（50 MHz）约束下完成 HLS synthesis、IP packaging 和 Vivado out-of-context implementation。

这证明当前 Hybrid LIF readout head 在 50 MHz 约束下具备实现余量，但本报告还不是 Zynq PS + PL 系统 bitstream，也不是开发板回放结果。

## 配置

```text
Top: hybrid_lif_head_q12_6
Part: xc7z020clg400-1
Clock: 20 ns / 50 MHz
Flow target: vivado
Implementation: Vivado out-of-context generated by Vitis HLS
```

可复现入口：

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass `
  -File hls/hybrid_lif_head/scripts/run_impl_50mhz.ps1
```

脚本先执行匹配的 HLS compile/synthesis，再执行 `vitis-run --mode hls --impl`。默认生成目录为被忽略的 `hls/hybrid_lif_head/impl_50mhz_work/`；也可通过 `-WorkDir` 指定临时目录。

## 过程中的工具问题

1. 直接运行 `vitis-run --mode hls --impl` 会提示缺少 `hls/syn`。原因是 implementation 依赖先完成 HLS compile/synthesis；脚本现在先运行 `v++.bat -c --mode hls`，再运行 `vitis-run --impl`。
2. 在未执行 C synthesis 时直接运行 `--package` 会提示 `Must run csynth_design before export_design`。本任务使用先综合、后打包的流程。
3. 直接打开旧 `cnn_lstm` Vivado 工程时，发现其工程内仍含历史 C 盘路径、失效的 `hlsip` 路径和 Windows 260 字符路径问题。因此本次没有修改旧 CNN-LSTM 工程，而是只复用其文档中记录的 Zynq/PS/FCLK/AXI/UART 集成模式。

## 证据边界

本次结果可以支持：

- Q12.6 Hybrid LIF readout head 在目标器件和 50 MHz 约束下完成 Vivado OOC implementation；
- 当前 IP 的实现资源和时序有可复现报告；
- 该 IP 可以进入下一步 Zynq PS/PL 集成。

本次结果不能支持：

- 已经生成完整 Zynq 系统 bitstream 或 XSA；
- 已经下载到开发板运行；
- 已经完成 PS-PL 数据传输和 UART 回放；
- 已经完成完整 CNN-SNN Accuracy、端到端延迟或功耗测量。
